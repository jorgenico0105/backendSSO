# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run start:dev                 # API en http://localhost:3000/api (escucha en 0.0.0.0 para el teléfono)
npm run build                     # nest build
npm run lint                      # eslint --fix (prettier incluido)
npx tsc --noEmit                  # typecheck
npm run migration:generate -- src/database/migrations/Nombre   # requiere DB_SYNC=false y la BD existente
npm run migration:run
```

There are no meaningful tests yet (the scaffold specs were removed).

## Setup

Copy `.env.example` to `.env`. You need MySQL 8 credentials (`DB_*`), `OPENAI_API_KEY` and `CLOUDINARY_*`, plus the `ERGO_*` vars that point at the posture service in `../ergonomic-poses` (its `API_KEY`/`WEBHOOK_SECRET` must match `ERGO_API_KEY`/`ERGO_WEBHOOK_SECRET`). `../dev.sh` starts this API and that service together. With `DB_SYNC=true` (local only), startup creates the `sst_prevencion` database if it is missing (`ensureDatabase` in `src/database/typeorm.config.ts`) and TypeORM synchronizes the tables. `SeedService` then seeds the `features` catalog and the super admin (`SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`, default `admin@sstprevencion.com` / `1`). The seed is idempotent and runs on every boot. For production, set `DB_SYNC=false`: the app then runs the migrations in `src/database/migrations` on boot (`migrationsRun`). After changing entities, generate a migration (`DB_SYNC=false npm run migration:generate -- src/database/migrations/Nombre`) against a DB with the previous schema. `Dockerfile` builds the production image; deployment is in `../deploy`.

## Architecture

NestJS 11 + TypeORM 1.x (MySQL). Every route has the global `/api` prefix. Code, tables, and messages are in Spanish.

- **Naming**: `SnakeNamingStrategy` maps camelCase properties to snake_case columns, and a `empresa` relation to `empresa_id`. Raw SQL in QueryBuilder must use the snake_case names.
- **Auth** (`src/auth`): `AuthGuard` is registered as `APP_GUARD`, so every route requires a JWT unless it is marked `@Publico()`. On each request it reloads the user from the DB into a `UsuarioSesion` (`id`, `perfil`, `features[]`, `empresaIds[]`), so admin changes to features or companies apply immediately. It also enforces `@SoloAdmin()` and `@RequiereFeature(...)` (any-of). The `ADMINISTRADOR` profile bypasses both checks and sees every company. Read the session with `@UsuarioActual()`.
- **Company scoping**: services must call `EmpresasService.asegurarAcceso(user, empresaId)` before touching company data. `EmpresasService.contexto()` loads company/area/position and validates that they belong together.
- **Tables**: `empresas` → `areas`, `puestos` (per company); `usuarios` ↔ `usuario_empresas`; `features` + `usuario_features` (bottom-menu access; codes are `FeatureCodigo` in `common/enums.ts`, mirrored as `FeatureCode` in the app). AI results go in `analisis_imagenes`, `analisis_videos` and `matrices_riesgo`, which share `AnalisisBase` (company, area, position, `creadoPor`, `iaRespuesta` JSON, model, duration). `clasificaciones` is the admin-editable catalog of immediate classifications (seeded once when empty). `permisos_trabajo` holds work permits. `evaluaciones_voz` is a leftover of the old NTP 330 flow and no longer has an entity.
- **AI agent** (`src/ia`): the SST knowledge and rules live in `agente-sst.prompts.ts`. `contextoEmpresa()` adds the company/area/position as context. `schemas.ts` defines the zod structured outputs. `OpenAiService.estructurado()` calls `responses.parse` with `zodTextFormat`. Structured Outputs forbids optional fields, so every field is required, and numeric ranges are clamped in the services rather than in the schema.
- **Flows** (`src/analisis`):
  - Photo of an unsafe act or condition: `POST /empresas/:id/reportes/analizar` uploads to Cloudinary, sends the URL to the agent, and saves the row as `ANALIZADO`. The agent decides acto vs. condición (the app no longer sends `tipo`) and fills classifications, severity, description, and measures; with no `areaId` it also picks one of the company's areas (`areaSugerida`). The row is saved as `ANALIZADO`, or as `ERROR` with the image so it can still be registered by hand. `PATCH /reportes/:id/registrar` stores the auditor's final data (including `accionCorrectiva`, the editable text the app prefills from the agent's immediate + hierarchy-of-controls measures) and assigns `INC-AAAA-NNNN`. The allowed classifications come from the `clasificaciones` table (`ClasificacionesService.nombresPorTipo()`); the agent's picks are filtered against it. CRUD lives at `/clasificaciones` (`@SoloAdmin` for writes).
  - Ergonomics (**no AI**): `POST /empresas/:id/ergo` takes an image or a video in the `archivo` field and forwards it to the Python posture service through `PosturalApiService`, which measures the pose with MediaPipe and returns RULA/REBA/OWAS plus a rule-based `informe`. An image is answered `ANALIZADO` right away. A video is saved as `PROCESANDO` with the service's `jobId`; it is completed by the signed webhook `POST /ergo/webhook` (`@Publico`, verified with `rawBody` + HMAC) or, as a fallback, the next time `GET /ergo/:id` is read, which also refreshes `progreso`. Key-frame thumbnails go to Cloudinary when it is configured and otherwise stay as data URIs, so ergonomics can be tested without Cloudinary or OpenAI. Rows live in `analisis_videos` for both media (`medio` column). The company listing is trimmed for the app's history: only the cover pose (first critical frame) and no `iaRespuesta`.
  - Voice → risk matrix (format F-PSSO-IMEC-02, one per area + position): `gpt-4o-transcribe`, then `MatrizVozIA` fills the header and picks hazards **only by code** from the 76-item catalog (the app's dictation guide walks the 7 risk factors and asks for peligro → probabilidad → consecuencia per hazard; the AI returns each hazard's literal `fragmento` of the transcript and `matriz/dictado.ts` reads baja/media/alta, LD/D/ED, grave/leve… from it deterministically, overriding the model's P/C; only what wasn't dictated keeps the AI estimate, with `justificacion` prefixed "Estimada por la IA:") in `analisis/matriz/catalogo.ts` (7 factors, generated from `Matrices INSST UNL 2026.xlsx`). Estimation = probability (1–3) + consequence (1–3) → T/TO/MO/I/IN, computed in `matriz/matriz.ts`, which also builds the action plan (one action per hazard, deadline by level) and `faltantes`: every required field still empty, with the AI's own message when it gave one. Known data (area, company province/city, SSO lead, position hours) is prefilled and passed to the prompt so it isn't flagged. `PATCH /voz/:id` saves the auditor's edits and recomputes everything; `estado` is `COMPLETA` only when nothing is missing. A previous matrix for the same area/position makes the new one `periodica`.
  - Work permits (`src/permisos`, feature `PERMISOS`): RSE-16-00-01 + ART RSE-16-00-02. The form sections travel as JSON (`datos`, `art`; shape defined in `mobile/src/domain/permits.ts`). `POST /permisos/:id/autorizar` requires personnel and section-8 approvers; `/cerrar` requires the section-9 report and section-10 closers plus the clean-area answer.
- **Legal and store compliance** (`src/legal`, `src/auth`): `/terminos`, `/privacidad`, `/soporte` and `/eliminar-cuenta` are public HTML pages served outside the `/api` prefix (excluded in `main.ts`); their text is in `legal.textos.ts` and the provider/contact come from `LEGAL_TITULAR`, `LEGAL_IDENTIFICACION`, `LEGAL_EMAIL` and `LEGAL_CIUDAD`. Bumping `VERSION_LEGAL` makes every user accept the terms again (`/auth/me` returns `legal.aceptada`; `POST /auth/consentimientos` records it). Sending photos or audio to OpenAI requires the user's separate AI consent (`usuarios.consentimiento_ia`, checked with `exigirConsentimientoIa` in the image-analysis, transcription and voice-matrix endpoints). `POST /auth/eliminar-cuenta` (password confirmation) anonymizes and deactivates the account and removes its accesses; records stay with the company, and the last active admin can't delete itself.
- **Cloudinary** (`src/cloudinary`): folders `CLOUDINARY_FOLDER/empresas/{id}/{logo|actos|ergo|voz}`. Audio is uploaded as `resource_type: video`.
